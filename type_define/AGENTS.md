# 작업 그래프 계약 지침

## 이 디렉터리의 책임

`Task`·`Graph`와 요약 구조처럼 여러 파이프라인 모듈이 공유하는 자료형과 상태 표현을 관리한다. 공통 규칙은 루트 [AGENTS.md](../AGENTS.md)를 따른다.

## 이 디렉터리만의 규칙

- `Task`의 상태값, candidate list, 필요 agent 수, predecessor와 직렬화 필드의 의미를 바꾸면 Task Manager·Controller·로그 소비자에 미치는 영향을 함께 확인한다.
- `Graph.edge`는 선행관계이며 수치 가중치가 아니다. 현재 `add_edge()`는 순환을 막지 않으므로 그래프를 DAG라고 가정하는 새 분석에는 순환·누락 node 검사를 먼저 둔다.
- 그래프 조작은 node·edge·상태의 일관성을 보존해야 한다. ready 판정과 그래프 변환은 작은 고정 fixture로 확인하고, 성공·실패 상태를 임의로 채워 통과시키지 않는다.
- LLM 호출, 배정 정책, Minecraft 행동 판단은 이 자료 계약에 넣지 않는다. 기존 그래프 출력 기능을 건드릴 경우 실험 로그 형식의 호환성도 확인한다.
