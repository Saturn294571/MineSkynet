# M4 — Cloud planner와 State Manager

상태: `[ ]` M3 capability 근거 확보 후 착수

## 목적

task 분해, capability-aware 후보 배정, 공유 상태, 실패 이력과 재계획을 중앙 control plane에 둔다.

## 작업

- [ ] 구조화 subtask와 dependency DAG schema
- [ ] agent capability·inventory·위치·진행 상태 schema
- [ ] skill retrieval와 candidate filtering의 cloud/controller 배치
- [ ] task history·failure trace 저장과 planner/reflector 재계획
- [ ] 검증된 skill만 읽는 `mineskynet-core` read-only registry
- [ ] E4 Full service의 능동 skill 쓰기와 core 경계 분리
- [ ] API token·비용·latency와 decision trace 기록

## 완료 조건

cloud planner가 여러 local executor에 작업을 배정하고 공유 상태와 실패 근거로 재계획해야 한다.
