# M1 — Fixed-candidate 실제 actor 검증

상태: `[ ]` E1 이후 base actor부터 시작  
검증 Gate: [E2](./E2.md)

## 목적

stateless short-context actor가 제한된 candidate 중 정확한 skill 하나를 선택할 수 있는지 평가하고, 파인튜닝의 필요성을 baseline 뒤에 판단한다.

## 진행 계획

- [ ] actor endpoint와 학습/eval sample schema 고정
- [ ] 파인튜닝하지 않은 약 4B급 instruct model baseline
- [ ] JSON validity·candidate validity·top-1·latency·메모리 기록
- [ ] online atomic task 결과와 offline accuracy 분리
- [ ] 동일 test set에서 base Gemma·LoRA Gemma·MineMA 비교
- [ ] 필요할 때만 INT4와 추가 LoRA 실험

## 2026-08-06 선행 실험 요약

Minecraft QA corpus 전처리와 Gemma 3 1B BF16 LoRA 파이프라인은 E0보다 먼저 시험됐다.

- [x] 원본 390,317행을 감사하고 구조 오류·빈 값·placeholder 815행, exact 중복 10,131행 제거
- [x] clean 379,371행을 question hash 기준 train 341,282 / validation 19,109 / test 18,980으로 분리
- [x] 128·1k·10k profile에서 finite loss, adapter 저장·재로드와 단일 추론 확인
- [x] peak VRAM 약 3.93·4.14·4.23 GiB, runtime 171·138·865초 기록
- [~] 제작대 판자 단일 probe는 base `6`, 128·1k adapter `4`, 10k adapter `6`; 데이터 규모 효과는 입증되지 않음
- [!] QA 단일 probe와 token accuracy는 actor skill-selection 성능 근거가 아님

결론: 학습 파이프라인은 작동하지만 Gemma actor의 유효성과 QA 데이터의 적합성은 미검증이다. 추가 학습은 E0·E1 통과와 E2 base baseline 뒤에만 재개한다.
