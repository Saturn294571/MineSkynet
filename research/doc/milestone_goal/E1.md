# E1 — `e1-stub` 최소 controller 검증

상태: `[ ]` E0 완료 후 착수  
연결 마일스톤: [M0.5](./M0_5.md)

## 목표

모델 품질을 배제하고 controller → deterministic stub actor → strict registry → executor → verifier 계약을 검증한다.

## 작업

- [ ] `Odyssey()` eager initialization을 거치지 않는 minimal controller entrypoint
- [ ] observation·subgoal·candidate skills·request ID schema
- [ ] candidate를 `mineWoodLog`, `craftCraftingTable` 두 개로 제한
- [ ] deterministic `/v1/actor/select` stub
- [ ] exact skill ID와 whitelist 검증; unknown skill silent fallback 금지
- [ ] inventory/world-state delta를 쓰는 일반 verifier schema
- [ ] timeout·connection·parse·invalid skill·execution·verification 오류 분류
- [ ] request/response와 verifier 결과의 구조화 로그
- [ ] 두 atomic task를 전체 경로에서 각각 10/10 통과

## 통과 조건

모델 없이 두 task 모두 전체 controller 경로에서 10/10 성공하고, 잘못된 skill과 각 오류 유형이 명시적으로 거부·분류돼야 한다.
